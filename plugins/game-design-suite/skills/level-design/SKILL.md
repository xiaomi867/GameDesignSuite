# 关卡设计

## 先明确目标

- 本关要教什么/考什么；
- 玩家已有能力；
- 新引入能力；
- 目标时长；
- 难度位置；
- 失败与恢复；
- 制作预算；
- 性能约束。

## 空间指标

根据项目建立必要 Metrics：

- 移动速度；
- 跳跃/冲刺距离；
- 攻击距离；
- 视野；
- 转角；
- 门宽；
- 通道宽度；
- 房间尺度；
- 敌人出生距离；
- Checkpoint 间隔。

不靠“感觉差不多”。

## Layout

检查：

- 主路径；
- 支路；
- 回环；
- 地标；
- 导航；
- 视线；
- 高低差；
- 节奏；
- 安全区/压力区；
- 探索奖励；
- 返回成本。

## Encounter

空间要服务战斗考题。与 `combat-design` 协作确认：

- 敌人类型；
- 出生；
- 视线；
- 距离；
- 掩体；
- 退路；
- 资源；
- 压力和恢复。

## 教学节奏

可采用：

`Introduce -> Develop -> Twist -> Test`

但只在适合当前项目时使用。

## Playtest

记录：

- 玩家路线；
- 迷路点；
- 死亡点；
- 停滞；
- 资源耗尽；
- 错误理解；
- 是否看见引导；
- 预期路径 vs 实际路径。

文档或未游玩地图不能证明关卡体验已验证。
