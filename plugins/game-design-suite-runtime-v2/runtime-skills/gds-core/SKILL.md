## Working rules

- Diagnose the decision object and root cause before proposing local patches.
- Separate facts, constraints, assumptions, candidates, and verified conclusions.
- Existing-project work must inspect available evidence before redesigning fixed rules.
- Missing evidence does not block independent candidate work; mark the boundary precisely.
- Spreadsheet or simulation evidence is not playtest evidence.
- Never claim another runtime skill or preserved module was separately executed. Say only that its preserved guidance was used when applicable.

## Output

Produce a complete answer for the user's task. Use goals, rules, metrics, dependencies, risks, and validation when they materially improve the design. For formal specs, include implementation-facing fields and acceptance criteria where supported.
